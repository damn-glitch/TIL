# TIL 3.0 — что сделано и все идеи

> Автор языка: Алишер Бейсембеков. Этот документ описывает обновление TIL до
> версии 3.0: что было изучено, что исправлено, что добавлено, как это проверено
> и какие идеи остаются на будущее. Всё, что помечено «✅ проверено», реально
> работает и покрыто тестами; ничего не является «заглушкой в комментарии».

## 0. Коротко

| Было (v2.0) | Стало (v3.0) |
|---|---|
| Работал только на ПК с Python **и** GCC | Работает: Python без GCC, любой C-компилятор, **процессоры калькуляторного класса** (ARM Cortex-M, 8-битный AVR — проверено в эмуляторах; Z80 — компилируется, но пока не помещается в 64 КБ) |
| «Революционные» `retry`, `timeout`, `#[pure]`, `#[cap]` — это комментарии в C | Все **настоящие**: `retry` реально повторяет, `timeout` реально прерывает бесконечный цикл, эффекты и возможности проверяются компилятором |
| `f"Hello {name}"` печатал адрес памяти | Исправлено (и ещё ~25 подтверждённых ошибок) |
| Казахский `немесе` ломал `elif`; латинский казахский из README не работал | Казахский (кириллица и латиница) и **русский** синтаксис, команда `til translate` |
| 255 тестов, многие проверяли только «компилируется ли» | 255 + **81 новый** тест; каждая программа запускается на трёх движках и сравнивается побайтно |

## 2. Что показало изучение языка

TIL v2.0 — это транслятор Python-подобного синтаксиса в C (`src/til.py`,
~5600 строк: лексер → парсер → проверка типов → генератор C → GCC).

**Сильные стороны (сохранены):** многоуровневая система `#[level: N]`,
структуры + `impl`, enum + `match`, контракты `requires/ensures`, казахские
ключевые слова, дружелюбные сообщения об ошибках.

**Главная проблема:** генератор C *угадывал* типы по именам переменных и по
умолчанию считал всё `int64_t`. Отсюда ошибки:

* `f"Hello {name}"` печатал число (адрес строки) — из-за двойного импорта
  модуля внутри парсера f-строк;
* `"he" + "llo" == "hello"` давало `false` (сравнивались указатели);
* `s += "b"` не компилировался; цикл по массиву строк объявлял `int64_t`;
* `f(x) -> int => x + 1` возвращал **0** — однострочные тела функций
  молча становились пустыми (ошибка `Block([...])` в датаклассах);
* файл, заканчивающийся двумя пустыми строками, не компилировался;
* казахское `немесе` было записано в словарь дважды (elif и or) — `elif`
  по-казахски не работал;
* пример на латинском казахском из README (`eger`, `turaqty`, `basyp_shygaru`)
  не работал вообще;
* `retry(n)` выполнял тело один раз, `timeout(ms)` был комментарием,
  `#[pure]` на функции с `print` позволял GCC удалить вывод;
* сообщения `assert`/`intent` позволяли внедрить произвольный C-код;
* импорт модулей терял константы, `mod.func()` не работал.

Все перечисленные ошибки **исправлены** и закрыты регрессионными тестами
(`tests/test_v3.py`, класс `TestFixedBugs` и др.).

## 3. Новое в TIL 3.0

### 3.1 TIL VM — один язык для ПК, калькуляторов и микроконтроллеров ✅ проверено

Второй бэкенд: программа компилируется в компактный **байткод** (`.tbc`),
который выполняет маленькая виртуальная машина.

```bash
til run --vm game.til              # без C-компилятора (чистый Python)
til build --target vm game.til     # -> game.tbc (любой TIL VM)
til build --target c-vm game.til   # -> game_vm.c: VM + программа в ОДНОМ C-файле
```

* **Эталонная VM** на Python (`til run --vm`, REPL) — нужен только Python.
  Если на компьютере нет GCC, `til run` автоматически запускает программу на VM.
* **Переносимая VM на C** (`vm/tilvm.c`) — C99, **без malloc**, всё состояние в
  одной структуре, байткод может лежать во флеш-памяти/ПЗУ.
* **Сборщик мусора со сжатием** (mark-compact): нет фрагментации даже на куче
  в 2–4 КБ; ссылки — это смещения, поэтому объекты можно двигать.
* **Настраиваемость**: целые 16/32/64 бит, вещественные: нет / float / double,
  размер кучи, стека, глубины вызовов.

**Проверено на эмулированных процессорах калькуляторного класса** (каждый пример
сравнивается побайтно с эталоном):

| Процессор | Класс устройств | Эмулятор | Память VM | Результат |
|---|---|---|---|---|
| ARM Cortex-M3, 64 КБ ОЗУ | NumWorks, STM32 | QEMU | 44.7 КБ кода, 24 КБ ОЗУ | 17 из 17 программ совпадают* |
| 8-битный AVR ATmega1284P, 16 КБ ОЗУ | Arduino | simavr | 53.8 КБ кода, 10.5 КБ ОЗУ | 17 из 17 совпадают |
| Z80 | TI-83 / TI-84 | ucsim (SDCC) | компилируется, но 70.7 КБ кода | **пока не помещается** в 64 КБ адресного пространства — см. `vm/ports/z80/RESULTS.md` |

\* на одинарной точности последняя цифра некоторых float может отличаться (`78.5397`/`78.5398`) — это свойство типа `float`.

**Скорость:** переносимая VM на C считает `fib(27)` за 0.052 с — как CPython
(0.056 с); нативный бэкенд — 0.010 с.

### 3.2 «Гибернация» программ (снимки состояния) ✅ проверено

Работающую программу можно **остановить, сохранить и продолжить позже** — даже
после выключения калькулятора:

```bash
tilvm --snapshot-after 300 state.snap prog.tbc   # пауза после 300 шагов
tilvm --resume state.snap prog.tbc               # продолжение с того же места
```

Тест проверяет, что вывод «до паузы» + «после возобновления» побайтно равен
выводу непрерывного запуска. Также есть бюджет шагов (`tilvm_run_steps`) для
кооперативной многозадачности и песочница `--max-steps`.

### 3.3 «Революционные» возможности стали настоящими ✅ проверено

| Возможность | Что делает теперь | Где работает |
|---|---|---|
| `retry(n) { … } else { … }` | при **любой** ошибке выполнения (assert, контракт, выход за границы, unwrap None, `panic`, timeout) тело реально выполняется снова; потом `else` с переменной `error` | VM и нативный C |
| `timeout(ms) { … } else { … }` | реально прерывает долгие вычисления, даже бесконечный цикл в другой функции | VM и нативный C |
| `intent "цель" { … }` | ошибка внутри сообщает, **что** код пытался сделать: `intent 'parse config' failed: bad token` | VM |
| `#[pure]`, `#[effects: io]` | **постепенная система эффектов**: эффекты выводятся из тела и вызовов, объявленные — проверяются компилятором (`E-EFFECT`) | оба |
| `cap X`, `#[cap: X]` | **безопасность на возможностях**: функцию с возможностью может вызвать только функция с той же возможностью (или `main`); даже взятие ссылки на функцию проверяется (`E-CAP`) | оба |
| `#[requires]`, `#[ensures]` | при константных аргументах нарушение находится **при компиляции** (`E-CONTRACT`), иначе — проверка во время выполнения (её можно перехватить `retry`) | оба |
| `assert`, `invariant` | восстанавливаемые ошибки с номером строки | оба |

Пример:

```python
var attempts = 0

flaky() -> int
    attempts += 1
    assert attempts >= 3, "ещё рано"
    return attempts * 10

spin() -> int
    var i = 0
    loop
        i += 1
    return i

main()
    let r = retry(5)
        flaky()              # реально 3 попытки -> 30
    print(r)
    let t = timeout(50)
        spin()               # реально прерывается через 50 мс
    else
        "сдались: " + error
    print(t)                 # "сдались: timeout"
```

### 3.4 Язык стал богаче

* **Замыкания как значения** (захват по ссылке), функции высшего порядка:
  `xs.map(|x| x * x).filter(...).reduce(...)`, `each`, `any`, `all`.
* **Алгебраические типы данных**: варианты enum с данными и сопоставление с
  образцом с деструктуризацией:
  ```python
  enum Expr
      Num(int)
      Add(Expr, Expr)

  eval(e: Expr) -> int
      return match e
          Expr.Num(n) => n
          Expr.Add(a, b) => eval(a) + eval(b)
  ```
* **Трейты с методами по умолчанию** и динамическая диспетчеризация;
  сигнатуры методов трейта без тела.
* **Option/Result + `?`**: раннее возвращение ошибки, `match` по
  `Some(x)/None/Ok(v)/Err(e)`, методы `unwrap/unwrap_or/expect/is_some/...`
  (и в нативном бэкенде).
* **Сопоставление с образцом**: литералы, строки, диапазоны `1..5`,
  альтернативы `1 | 2 | 3`, кортежи/массивы `(a, b)`, структуры
  `Point { x: px, y: py }`, условия `n if n > 0`.
* **Словари** с сохранением порядка, `{"a": 1}`, `m["k"] += 1`, `keys/values/get_or/delete`.
* **Строки**: `split/join/replace/count/repeat/slice/trim/to_upper/...`, `"n=" + 42`.
* **f-строки с форматом**: `f"{pi:.2f} {255:x} {7:03} {0.25:%} {x:>8}"`.
* **Конвейер** `x |> f |> g(1)`, **цепочки сравнений** `0 <= i < n`,
  `-2 ** 2 == -4`, `else if`, `%=`, `0o17`, `\x41`, `\u{1F600}`.
* **Режим сценария**: `print("Привет")` — уже полная программа; глобальные
  переменные инициализируются в порядке записи.
* **Структурное равенство** массивов, словарей и структур.
* `let` действительно неизменяем (ошибка компиляции с подсказкой `var`),
  неизвестное имя — ошибка с подсказкой «did you mean …».
* Ошибки выполнения показывают **строку и стек вызовов TIL**:
  `runtime error: index out of bounds … at f (line 2) at main (line 4)`.

### 3.5 Казахский, латинский казахский и русский синтаксис ✅ проверено

* Кириллический казахский работает всегда (как раньше), `elif` пишется
  `әйтпесе егер`; `немесе` — это `or`.
* `#[lang: kk-latn]` — латинский казахский (как в README: `eger`, `aitpese`,
  `ushin … ishinde`, `turaqty`, `basyp_shygaru`, `negizgi`).
* `#[lang: ru]` — русский: `если/иначе/для/в/пока/вернуть/пусть/перем/функция/
  структура/выбор/и/или/не/истина/ложь`, `печать`, `главная`.
* **`til translate --to ru|kk|kk-latn|en файл.til`** — перевод программы между
  языками ключевых слов. Перевод EN → RU → KK-латиница → EN возвращает
  **исходный текст символ в символ** (проверено на всех примерах).

```python
#[lang: ru]
функция факт(н: int) -> int
    если н <= 1
        вернуть 1
    вернуть н * факт(н - 1)

главная()
    печать(факт(6))     # 720
```

### 3.6 Инструменты

| Команда | Назначение |
|---|---|
| `til run file.til` | нативно; если GCC нет или программа использует возможности VM — автоматически на VM |
| `til run --vm` / `--cvm` | эталонная VM / VM на C |
| `til build --target native\|vm\|c-vm\|c` | исполняемый файл / байткод / один C-файл для устройства / C-код |
| `til exec file.tbc`, `til dis file` | запуск и дизассемблер байткода |
| `til check file.til` | синтаксис + эффекты + возможности + контракты + имена |
| `til translate --to ru` | перевод ключевых слов |
| `til repl` | REPL на VM: мгновенно, без GCC, переменные сохраняются |
| `--max-steps N`, `--strip`, `--no-verify` | песочница, минимальный байткод, отключение проверок |

### 3.7 Как это проверено

* `tests/test_compiler.py` — 255 старых тестов: **все проходят**.
* `tests/test_v3.py` — 81 новый тест. Каждая программа выполняется на **трёх
  движках** (нативный C, VM на Python, VM на C), вывод должен совпадать побайтно.
* Все 255 старых тестовых программ дополнительно прогнаны на обеих VM — совпадают.
* VM на C прогнана под **AddressSanitizer + UBSan** с кучей 4 КБ (сотни сборок
  мусора со сжатием) — ошибок памяти нет.
* Запуски на эмулированных ARM Cortex-M3 и AVR — см. 3.1.

## 4. Идеи на будущее (дорожная карта)

Это идеи, которые логично продолжают сделанное. Они **ещё не реализованы**.

1. **Компилятор прямо на калькуляторе.** Написать компилятор TIL на самом TIL
   (самохостинг) и скомпилировать его в байткод — тогда калькулятор сможет
   компилировать программы сам, без ПК.
2. **Миграция программ между устройствами.** Переносимый формат снимка
   (значения, а не байты памяти): начать вычисление на ПК, продолжить на
   калькуляторе — «телепортация» работающей программы.
3. **Графика и клавиатура калькулятора** как встроенные функции:
   `draw_pixel`, `draw_line`, `draw_text`, `key_pressed` — одинаковые на всех
   устройствах, игры на TIL для TI/Casio/NumWorks.
4. **Отладка с путешествием во времени** на основе снимков каждые N шагов:
   шаг назад, воспроизведение ошибки.
5. **Онлайн-песочница на сайте**: VM на C → WebAssembly, настоящий запуск TIL
   в браузере (сейчас «playground» на сайте только показывает заготовку).
6. **Доказательство контрактов** через SMT-решатель (Z3): `#[requires]` и
   `#[ensures]` доказываются при компиляции для всех входов, а не только для
   констант. Это сделает уровень 4 (Formal) настоящим.
7. **Типизированное AST для нативного бэкенда** и мономорфизация обобщений —
   чтобы нативный C поддерживал всё, что поддерживает VM.
8. **Алгебраические эффекты с продолжениями** (`perform`/`handle` с
   возобновлением) — механизм снимков VM уже умеет «замораживать» вычисление.
9. **TIL на Z80 (TI-83/84)**: 16-битная сборка VM (сейчас SDCC падает с
   внутренней ошибкой), страничная Flash-программа для TI-84 Plus или порт
   на TI-84 Plus CE (eZ80, без ограничения 64 КБ).
10. **Статическая оценка памяти**: компилятор доказывает, что программа
   поместится в 4 КБ кучи калькулятора, ещё до загрузки.
11. **Энергосбережение на устройствах**: `#[energy: low]` → VM снижает частоту
    шагов и засыпает между ними.
12. **Сообщения компилятора на казахском и русском** (сейчас — на английском).
13. **Быстрее VM**: суперинструкции, `computed goto`, кэш методов —
    ожидаемо в 2–3 раза быстрее на тех же устройствах.
14. **Менеджер пакетов** и LSP, у которого ключевые слова берутся прямо из
    `til.py` (сейчас списки в редакторах дублируются вручную).
