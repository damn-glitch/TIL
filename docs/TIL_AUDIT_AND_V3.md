## 0. Вердикт за 30 секунд

TIL сегодня — это **тонкий слой Python-образного синтаксиса поверх транслятора в
C**, у которого большинство заявленных возможностей не существует в реализации.
Ядро (арифметика, функции, структуры+методы, enum+match, циклы, локальные
замыкания, рантайм-контракты `#[requires]/#[ensures]`, казахские ключевые слова)
**действительно работает**. Но почти всё, что вынесено в маркетинг как
«революционное», — это комментарии в сгенерированном C.

| Показатель | Реальность |
|---|---|
| Тестов «проходит» | 255/255 — но ~половина проверяет *наличие подстроки* в C или «не упало», а не поведение |
| «Революционных» фич v2.0 | 10 заявлено, **0 имеют семантику** (все → комментарии/no-op) |
| Строковое `==` | Сравнение **указателей**, не значений → `("he"+"llo") == "hello"` даёт `false` |
| Option / Result / tuple / dict | Практически **не извлекаются / не компилируются** end-to-end |
| Инъекция C-кода | **2 подтверждённых вектора RCE-класса** (через `intent` и `assert`) |
| «Safe» уровень (bounds-check) | **Дырявый**: параметры-массивы, поля структур, `while`-условия не проверяются → OOB / segfault |
| Утечки памяти | Каждая конкатенация строк течёт; во всём компиляторе **один `free(`** и он не используется |
| «Faster than C» | Ложь — опровергнуто собственной таблицей бенчмарков в доках |
| Лицензия | Файл — BSL 1.1, но 3 документа заявляют MIT / «open source» |

**Что делать (кратко):** есть два трека. **Трек A** — честный ремонт v2.x: убрать
ложные заявления, починить ~15 корневых багов (почти все растут из одного —
вывод типов по умолчанию сваливается в `int64_t`). **Трек B** — v3 «Революция»:
взять единственную реально уникальную идею (по-настоящему многоуровневая
верификация + мультиязычный синтаксис) и сделать её настоящей, выкинув 20 фейковых
фич. Подробности — разделы 4 и 5.

## 1. Методология

- **4 агента-зонда** проверяли конкретные гипотезы о багах (30 проб, P1–P30):

## 2. Корневая причина №1 (из неё растёт половина багов)

Прежде чем перечислять симптомы — **главный архитектурный дефект**, порождающий
непропорционально много ошибок:

> **Вывод типов при `let x = <выражение>` по умолчанию сваливается в `int64_t`.**
> `infer_c_type` (`src/til.py:4905`) и `_infer_expr_print_type` (`:3927`) обрабатывают
> лишь узкий набор форм. Всё незнакомое → `int64_t`. Плюс типы «протекают» только
> через плоские множества `string_vars/float_vars/...`, а не через настоящую
> типизированную AST.

Прямые следствия (каждое подтверждено):

- `let a = "he" + "llo"` → `int64_t a = til_str_concat(...)` — указатель кладётся в
  `int64_t`. (P1)
- `let o = Some(5)` → `int64_t o = til_Some_int(5)` — структура кладётся в `int64_t`. (P7)
- `let t = (1,2,3)` → `int64_t t = (TIL_Tuple_0){...}` — тип не тот **и** typedef
  вообще не сгенерирован. (P3)
- Переменная цикла, элемент comprehension, элемент массива структур, часть f-строки
  — **всё хардкодится в `int64_t`**, из-за чего фичи не «складываются» друг с другом
  (см. 2.9, F1). (design/F1)

**Вывод:** чинить точечно каждый симптом бессмысленно — нужна единая типизированная
инфраструктура (каждый AST-узел несёт `Type`, codegen берёт тип из узла, а не
угадывает по имени переменной). Это фундамент и для v2.x-ремонта, и для v3.

## 3. Каталог дефектов по подсистемам

Формат: **симптом → причина (`файл:строка`) → доказательство → как чинить.**
Severity: 🔴 critical / 🟠 high / 🟡 medium / ⚪ low.

### 3.1 Строки

**🟠 Строковое `==` — сравнение указателей, а не значений.**
`gen_BinaryOp` (`:4248`) маппит `==` в C `==`; спец-обработка есть только у `+`.
Доказательство: `let a="he"+"llo"; let b="hello"; print(a==b)` → **`false`**.
`"abc"=="abc"` даёт `true` лишь из-за пулинга литералов gcc; для строк, собранных в
рантайме, — всегда `false`. То же в `match` по строке (`_match_val == "abc"`). (P1)
*Чинить:* в `gen_BinaryOp` для `==`/`!=`, если хоть один операнд строковый —
генерировать `til_str_eq(a,b)` (хелпер уже есть, `:3080`). В `match` по строке —
цепочка `strcmp`, а не `switch`.

**🟠 `s += "b"` не компилируется.**
`gen_Assignment` (`:3784`) для составных операторов выводит текст буквально →
`s += "b";` → gcc `invalid operands to binary +`. (P2)
*Чинить:* переписывать `x += y` как `x = til_str_concat(x, y)` для строк.

**🟠 Каждая конкатенация течёт.**
`til_str_concat` (`:3071`) делает `malloc` и никогда не освобождает. Во всём
компиляторе ровно один `free(` — неиспользуемый `til_free`. valgrind на цикле из 1000
конкатенаций: `501,500 bytes definitely lost, 1000 allocs / 1 free`. f-строки и
comprehension текут так же. (P25)
*Чинить:* нужна модель владения (арены/regions или Rc) — фундаментальное решение, см. v3.

### 3.2 Option / Result / tuple / dict — заявлены, но нефункциональны

**🔴 Tuple вообще не компилируется.** `gen_TupleLit` (`:4596`) ссылается на
`TIL_Tuple_0`, но метода, который бы генерировал typedef, **не существует** (только
комментарий `_fixup_tuples` на `:4615`). `let t=(1,2.5,"x")` → gcc
`'TIL_Tuple_0' undeclared`. (P3)

**🟡 Dict-литерал — no-op с мусором.** `gen_DictLit` (`:4670`) выводит TODO-комментарий
и `NULL`. `let d={"a":1}; print(d["a"])` печатает `97` (арифметика указателей по
`"a"`), а не `1`. (P4)

**🟠 `Err(...)` всегда `til_Err_int`.** Для `Result<str,str>` тело
`return til_Err_int("boom")` при сигнатуре `TIL_Result_str` → gcc `incompatible types`.
`Ok` типизируется, `Err` — нет. (P6)

**🟠 Option/Result фактически «только на запись».** `match` по `Some(x)/None` не
делает деструктуризацию (`Some(x)` превращается в **вызов конструктора**, `x` не
связывается → `'x' undeclared`); `.unwrap()` не подключён (хелперы `til_unwrap_*` —
мёртвый код); `?` сломан (см. 3.6). Единственный способ достать значение —
недокументированный доступ к сырому C-полю `o.value` после явной аннотации
`let o: Option<int>`. (P7)

**🔴 Порядок объявлений ломает любую функцию, возвращающую Option/Result.**
Форвард-декларация `TIL_Option_int til_find(...)` выводится на строке ~17, **до**
`typedef ... TIL_Option_int` (~170) → gcc `unknown type name`. То есть даже корректная
функция-обёртка не скомпилируется. (P5/P6)
*Чинить:* Option/Result/tuple — это, по сути, дженерики. Их нельзя «залатать»; нужен
настоящий монолитный проход мономорфизации + корректный порядок эмита типов (см. v3).

### 3.3 «Революционные» фичи = комментарии

Каждая проверена: аннотация просто исчезает в комментарий C или игнорирует свой
параметр. Тесты «проходят» лишь потому, что проверяют арифметику *под* аннотацией.

| Фича | Что на самом деле генерируется | Док/строка |
|---|---|---|
| `timeout(ms){…}` | `// Timeout: Nms` + обычный блок. 3 млрд итераций в `timeout(100)` шли 2.63 с. Нет `alarm/signal/setitimer` (хотя docstring врёт про них). | P10, F10 |
| `retry(n){…}` | Цикл, который **безусловно** ставит `success=true; break` на 0-й итерации → никогда не повторяет. | P9 |
| `#[cap: X]` / `cap X{…}` | `// Capability check: X` + неиспользуемая `#define`. Ноль ограничений. | F09 |
| `#[effects: io/fs]` | Полностью инертно. `#[pure]` → `__attribute__((pure))` **без** проверки чистоты (см. ниже). | audit-tests |
| `#[energy: low/high]` | Ребрендинг gcc `-Os`/`-O3`; `medium` — no-op. | F15 |
| `#[generic: T]` | `T til_f(T a)` буквально → gcc `unknown type name 'T'`. Мономорфизации нет. | P21 |
| `#[cross_level: A->B]` | Комментарий. | F14 |
| `intent "…"{…}` | `// INTENT: …` + тело как есть. Плюс это вектор инъекции (3.5). | P... |
| Channel/send/recv | AST-узлы есть, `gen_*` **отсутствуют**. «Distributed» = переименованный `Vec`. | F16 |

**🟠 `#[pure]` — активная миско­мпиляция.** `#[pure]`-функция, вызывающая `print()`,
получает `__attribute__((pure))`; gcc вправе удалить вызов. Подтверждено: на `-O0/-O1`
и `-O2 -fno-inline` побочный `print` **исчезает** без предупреждений. (P11)
*Чинить:* либо реально проверять чистоту (нет IO/мутаций) и только тогда ставить
атрибут, либо убрать атрибут.

### 3.4 Модули

- **🟡 `math_utils.square(5)`** → буквально `math_utils.square(5)` в C → `math_utils undeclared`.
  Работает только без префикса (так `examples/08_imports.til` и «обходит» баг). (P15)
- **🟠 `const` из модуля теряется.** `resolve_imports` (`:5217`) мёржит только
  `FuncDef/StructDef/EnumDef/ImplBlock`; `const` (это `VarDecl`) выкидывается →
  `import math; print(PI)` → `PI undeclared`. Т.е. константы stdlib недоступны. (P16, F2)
- **🟠 Вложенные импорты не рекурсируют** → линкер `undefined reference to til_b_func`. (P17)
- **🟠 Установленный тулчейн сломан:** `install.sh` качает **только** `til.py`, но
  `ModuleResolver` ищет `stdlib/` рядом с компилятором. После установки
  `import math/strings` не компилируется. (infra)

### 3.5 Безопасность

**🟠 Инъекция C-кода через `intent` (RCE-класс).** `gen_IntentBlock` (`:5085`) кладёт
описание в однострочный `//`-комментарий, не убирая `\n`, который лексер разрешает в
строках. `intent "hello\nexit(123);"` → в C появляется живой `exit(123);`.
**Подтверждено: программа завершилась с кодом 123.** (TIL-001)

**🟠 Инъекция через `assert`/`invariant`.** `gen_AssertStmt` (`:4986`) экранирует
только `"`, но не `\` (и в неверном порядке). Сообщение вида `\"` закрывает строковый
литерал C → инъекция `); exit(123); //`. Подтверждено компиляцией инъектированных
токенов. (TIL-002)

**🟡 «Safe» уровень дырявый.** `gen_Index` (`:4346`) ставит `til_bounds_check` только
если объект — «голый» `Identifier`, зарегистрированный в `array_vars`. Параметры-массивы,
поля структур, индексы через выражения — **без проверки**. Подтверждён OOB-чтение
параметра-массива (`readit(a,20)` → мусор из стека, exit 0). (TIL-003, S11)

**🟡 Bounds-check двойно вычисляет индекс.** `arr[v.pop()]` → `pop()` вызывается
дважды (в проверке и в доступе); проверяется **другой** индекс, чем читается. (P13)

**🟡 Bounds-check в `while`-условии поднят наверх и выполняется один раз** для
начального индекса → per-iteration доступы неконтролируемы → OOB segfault без
сообщения. (P14)

**🟡 `match` со смешанными типами веток → segfault.** Тип результата берётся из
**первой** ветки. `1 => "hello"; 2 => 42` даёт `const char* r = 42;` → разыменование
`0x2A` → SIGSEGV. TIL не выдаёт диагностики. (P12)

**🟡 REPL пишет в фиксированный `/tmp/til_repl`** → symlink/TOCTOU на многопользовательских
системах. (TIL-006)

**⚪ Коллизия манглинга имён.** `é` → `_u00e9`, что совпадает с буквальным ASCII-идентификатором
`_u00e9` → `redefinition`. Схема не инъективна. (TIL-005)

**🟡 `gen_StringLit` не экранирует `\r`, `\0` и др. control-байты** → `\r` ломает
компиляцию, `\0` молча обрезает строку. (TIL-004)

### 3.6 Семантика языка

- **🟠 Иммутабельность `let` не обеспечивается.** Переприсваивание — лишь `Warning: Line 0`
  на stderr, программа компилируется и запускается. `let arr`/`let struct` свободно
  мутируются через индекс/поле (проверяется только присваивание голому идентификатору).
  Повторный `let x` молча ре-биндит ту же C-переменную. (F02, S1–S3)
- **🟠 Лексического шэдоуинга нет.** `declared_vars` — плоское множество на функцию.
  Внутренний `let x` в блоке **мутирует внешнюю** переменную (док обещает `10,20,10`,
  на деле `10,20,20`). Переменная `for` утекает в область функции. (S4, S10)
- **🟠 Несогласованная модель памяти.** Получатель метода `self` — по ссылке (мутирует
  через `let`!), другие struct-параметры — по значению, `let b = a` для структуры не
  компилируется (`int64_t b = a`). Нет `&self`/`&mut self`, нет ownership. (S6)
- **🟠 Нет истории null / ошибок.** `None` → `NULL`, свободно приводится к `int` (даёт 0).
  `?` — это abort-on-null с двойным вычислением операнда (а сейчас ещё и с пустыми
  операндами → не компилируется вовсе). Нет `try`, нет early-return. (S7, S8, P5)
- **🟠 `**` всегда → `pow()` (double).** `(10 ** i) % 7` не компилируется
  (`double % int`). Целочисленной степени нет. Плюс `-2 ** 2 == 4` (унарный минус
  связывает сильнее степени — против доков и Python). (S5, G4)
- **🟠 Многоуровневая система косметична.** Уровни 2/3/4 дают **байт-в-байт одинаковый**
  C. Уровень влияет лишь на (а) `always_inline` на 0/1 и (б) bounds-check на ≥2. Ни SIMD
  на 0, ни «формальных доказательств» на 4. Это **та самая «Mixed Martial Programming»**
  из патентной заявки. (S9, F14, F17)
- **🟠 Композиция фич ломается в 5 из 6 проверенных пар** (match+Option, f-string+метод,
  comprehension+структуры, Vec+for, for по массиву строк) — из-за хардкода `int64_t`. (design/F1)
- **🟠 f-строки для не-int печатают мусор.** `f"Hello {name}!"` → `snprintf(..,"%lld",name)`
  → печатает указатель как число. Причина усилена **двойным импортом модуля**
  (`from til import ...` при запуске как `__main__` грузит второй экземпляр, и `isinstance`
  против `til.Identifier` всегда ложь). (F01 — critical)
- **🟠 Функции высшего порядка не работают.** Параметр-функция `f(x)` → `til_f(x)` →
  линкер-ошибка. Замыкание работает только как локальная переменная, вызываемая напрямую;
  передать его аргументом нельзя. (F3)
- **🟠 Chained comparison `a<b<c` → `(a<b)<c`.** `3<2<1` печатает `true`. Синтаксис
  приглашает к `if 0<=i<n`, семантика молча неверна. (G1)

### 3.7 Парсер / грамматика

- **🟠 `is_func_def`-эвристика делает невозможным top-level код.** Любой `name(args)`
  на верхнем уровне трактуется как определение функции. `print("hi")` без `main` →
  `Expected IDENT, got STRING`. (G2, P18)
- **🟡 Двойной синтаксис (отступы/скобки) подключён наполовину.** `main() { … }` для
  void-функции падает; отступы внутри `{}` не работают. (G3)
- **🟡 `'a'` vs `'ab'`** — тип литерала зависит от длины; `'a'` печатается как `97`. (G5)
- **⚪ Range имеет приоритет выше сдвигов** (`parse_shift` вызывает `parse_range`). (G6)
- **🟡 Числовые литералы роняют сырой Python-traceback.** `0x` → `int('0x',16)` →
  `ValueError`; `1e` → `float('1e')`. Частичный dedent к невыровненному уровню —
  вообще без ошибки (молчаливый мис-парс). (P29)

### 3.8 Tooling

- **🟠 LSP: framing по символам, а не по UTF-8-байтам** (`Content-Length`) → на любом
  не-ASCII документе (а язык рекламирует казахский!) поток десинхронизируется, ответы
  теряются. (tooling)
- **🟠 LSP — сирота:** ни один редактор его не запускает. VS Code-расширение вообще без
  LSP-клиента (нет `vscode-languageclient`), это просто обёртка `child_process.exec`. (tooling)
- **🟠 Дрейф ключевых слов ×6.** 9 keyword'ов v2.0 (`assert/invariant/intent/retry/…`)
  нет ни в одном из 5 tooling-копий; при этом подсвечиваются несуществующие
  (`use/nil/any/None`). Каждая грамматика дрейфует по-своему. (tooling)
- **🟡 IDE (PyQt6) не запускается headless**, тянет `pip install` на машине юзера,
  использует Windows-only `os.system("start …")`. (tooling)
- **⚪ Версии tooling (1.0.0/1.1.0) отстают от компилятора 2.0.0.** (tooling)

### 3.9 Инфраструктура и документация

## 4. Трек A — честный ремонт v2.x (быстрые победы)

Приоритезация по (эффект × усилие). Almost every codegen-bug имеет общий корень —
раздел 2.

**P0 — честность (часы работы, ноль риска):**
1. Убрать/переписать ложные заявления: «Faster than C», «Smarter than all», 10
   «революционных» фич пометить как *экспериментальные заглушки* или удалить.
2. Свести лицензию к одной (BSL **или** MIT) во всех файлах; поправить версию/год.
3. Убрать `pip install til-compiler` и фейковый playground с сайта; починить URL'ы
   на `damn-glitch/TIL`; убрать пустые ссылки на Releases.
4. `install.sh/ps1`: тянуть `stdlib/` (или встроить stdlib в `til.py`), пинить тег,
   добавить SHA256.

**P1 — безопасность (обязательно перед любым публичным использованием):**
5. Инъекции `intent`/`assert`/`invariant`: экранировать `\` **первым**, затем `"`,
   вырезать `\r\n\0`; никогда не класть пользовательский текст в однострочный `//`
   (использовать `/* */` с вырезанием `*/`, либо не эмитить вовсе).
6. `gen_StringLit`: полный эскейпинг control-байтов (или C-хексом `\xNN`).
7. REPL: `tempfile.mkstemp`, не `/tmp/til_repl`.

**P2 — корректность ядра (нужен типизированный проход, раздел 2):**
8. Единый вывод типов: каждый AST-узел несёт `Type`; codegen читает тип узла.
   Это чинит разом: строковые `let`, f-строки, tuple, Option/Result, цикл-переменные,
   элементы comprehension/массивов структур, композицию фич.
9. Строки: `==`/`!=`/`match` → `til_str_eq`/`strcmp`; `+=` → `til_str_concat`.
10. Bounds-check: проверять индексацию **любого** массива (параметры несут `_len`;
    поля структур; выражения — вычислять индекс во временную, проверять её, потом
    использовать — заодно чинит двойное вычисление и `while`-условие).
11. `match`: тип результата — унификация **всех** веток (или ошибка при несовместимости);
    для Option/Result — настоящая деструктуризация `Some(x)/Ok(x)/Err(e)`.
12. Порядок эмита: сперва все `typedef`, потом форвард-декларации функций.
13. Модули: мёржить `const`; рекурсивно резолвить импорты; либо реализовать
    квалифицированные вызовы `mod.func`, либо явно запретить их с внятной ошибкой.
14. `**`: целочисленная степень для int-операндов; отдельный `powf()`-builtin для float.

### 4.1 Уже применено в этой ветке (proof-of-concept патч)

Чтобы показать, что ремонт реален и безопасен (все 255 тестов остаются зелёными),
в этой же ветке уже внесены следующие фиксы и **проверены end-to-end**:

| Фикс | Было | Стало | Проверка |

## 5. Трек B — TIL v3 «Революция»: честный дизайн настоящего языка

Проблема нынешнего TIL — **20 фейковых фич вместо одной настоящей**. Революционность
не в длине списка `[x]`, а в одной идее, доведённой до конца и реально работающей.
У TIL есть **два зерна подлинной уникальности**, которые больше никто не собрал
чисто вместе:

> ### Killer-идея v3: «Verified Gradient» + родной мультиязычный синтаксис
>
> **Один язык — непрерывный градиент гарантий на функцию.** Ту же функцию можно
> «докрутить» от скриптового уровня (динамика, GC, ноль аннотаций) до
> proof-уровня (refinement-типы, проверяемые SMT-солвером контракты) — и
> **компилятор enforce'ит решётку доверия**: функция низкой гарантии не может
> вызвать функцию высокой без проверяемой границы. Это делает «Mixed Martial
> Programming» **настоящим** (сейчас — косметика). Плюс синтаксис по-настоящему
> локализуем (казахский и др.) через таблицу токенов — не хак, а фича.

Никто не отдаёт «gradual verification» как первоклассную, простую в использовании,
градуированную-по-функциям возможность. Rust даёт safety, но не proof; Dafny/F* дают
proof, но с высоким порогом входа и без «скриптового» конца; TypeScript даёт gradual
typing, но не gradual *verification*. Это и есть незанятая ниша.

### 5.1 Что оставить / выкинуть / добавить

| Оставить (работает и складывается) | Выкинуть (фикция) | Добавить (делает язык настоящим) |
|---|---|---|
| Отступ-блоки, функции, default-параметры | Фейковые `timeout/retry/cap/effects/energy/cross_level/intent/distributed` | Единая типизированная AST + HM-вывод типов |
| Структуры + `impl` + методы | Двойной синтаксис `{}`/отступы | Настоящие Option/Result + `?` c early-return |
| enum + `match` + гарды | Косметические 5 «уровней» → 1 escape-hatch `unsafe` | Реальные refinement-типы на верхних уровнях |
| Диапазоны, `for/while/loop` | «Faster than C» и пр. маркетинг | Одна модель памяти: value + explicit `&`/`&mut` **или** GC (выбрать!) |
| Рантайм-контракты `requires/ensures` | Указатели-которые-не-парсятся | Настоящие алгебраические эффекты с хендлерами (или хотя бы effect-typed IO) |
| Мультиязычные ключевые слова | Мёртвый tooling-дрейф | Границы доверия между уровнями (verified gradient) |
| Локальные замыкания | | Функции высшего порядка (настоящие closures-as-values) |

### 5.2 Архитектура компилятора v3

1. **Фронтенд с типизированной AST.** Каждый узел несёт `Type`. Убрать плоские
   `string_vars/float_vars`. Вывод типов — Hindley–Milner для ядра.
2. **Собственный IR + мономорфизация** перед C. Дженерики, Option/Result, tuple —
   реально инстанцируются. Порядок эмита типов гарантирован.
3. **C — по-прежнему бэкенд** (это разумно), но с honest-нарративом: «TIL ≈ near-C
   speed», не «faster than C». Опционально — QBE/LLVM позже.
4. **Модель памяти — выбрать одну.** Рекомендация: **регионы/арены по умолчанию**
   (детерминированное освобождение, чинит утечки строк/comprehension) + `Rc<T>` для
   разделяемого владения. Без «то по ссылке, то по значению».
5. **Уровни verified-gradient — настоящие:**
   - `#[level: script]` — динамика, GC-подобно, без аннотаций.
   - `#[level: safe]` (default) — статические типы, bounds-check, non-null.
   - `#[level: systems]` — `unsafe`-escape, ручное владение.
   - `#[level: proof]` — refinement-типы (`x: int where x > 0`), контракты, проверяемые
     Z3/SMT **на этапе компиляции**, а не рантайм-`if`.
   - **Enforcement решётки:** переход из более слабого уровня в более сильный требует
     явной проверяемой границы (компилятор её вставляет/проверяет).
6. **Self-hosting как веха** (как обещано в `WHY_TIL_IS_A_REAL_LANGUAGE.md`): сначала
   довести ядро, затем бутстрап компилятора на самом TIL.

### 5.3 Как выглядит TIL v3 (иллюстрация целевого синтаксиса)

```til
# --- script level: быстрый прототип, без церемоний ---
#[level: script]
scrape(url: str)
    let body = http.get(url)          # эффект IO выведен, не задекларирован
    return body.lines().filter(|l| l.contains("ERROR"))

# --- safe level (default): типы, non-null, bounds, настоящий Result + ? ---
parse_port(s: str) -> Result<u16, ParseError>
    let n = s.to_int()?               # ? делает early-return при Err
    if n < 1 or n > 65535
        return Err(ParseError.OutOfRange)
    return Ok(n as u16)

# --- proof level: refinement-типы, проверяются SMT на КОМПИЛЯЦИИ ---
#[level: proof]
divide(a: int, b: int where b != 0) -> int
    return a / b                       # деление на ноль статически исключено

# --- граница доверия: safe-функция обязана доказать предусловие,
#     иначе — ошибка компиляции, а не рантайм-краш ---
main()
    let p = parse_port("8080")?        # Result распакован через ?
    # divide(10, 0)                    # ← ошибка КОМПИЛЯЦИИ: b != 0 не доказано
    print(divide(10, p as int))        # ок: p доказуемо != 0

# --- тот же язык, казахский синтаксис — первоклассно, не хак ---
#[til: kk]
негізгі()
    тұрақты порт = parse_port("443")?
    басып_шығару(порт)
```

Ключевое отличие от нынешнего TIL: **каждая строка выше имеет семантику, которую
компилятор реально проверяет**, а не комментарий. `?` действительно делает
early-return; `where b != 0` действительно доказывается; граница уровней действительно
enforce'ится; казахский — действительно другой набор токенов того же языка.

### 5.4 Дорожная карта v3

- **M1 — Типизированное ядро.** Переписать вывод типов и codegen на типизированную
  AST. Чинит ~15 багов раздела 3 разом. Это фундамент.
- **M2 — Настоящие Option/Result/`?`/tuple/дженерики** через мономорфизацию.
- **M3 — Одна модель памяти** (регионы + Rc); устранить утечки.
- **M4 — Verified gradient v1:** уровни `script/safe/systems` с enforce'ом границ;
  `proof` со стартовым набором refinement-контрактов (интеграция Z3).
- **M5 — Эффекты** (effect-typed IO как минимум; алгебраические хендлеры как максимум).
- **M6 — Tooling из одного источника** (keyword-таблица генерирует LSP/грамматики),
  рабочий LSP в VS Code.
- **M7 — Self-hosting** ядра на TIL.

## 6. Итог

TIL — это **работающее маленькое ядро, погребённое под слоем нереализованного
маркетинга**. Хорошая новость: ядро здоровое, а почти все codegen-баги растут из
одной корневой причины (нетипизированный вывод → `int64_t`), так что «трек A»
чинит непропорционально много за счёт одного рефакторинга. По-настоящему
революционным язык делает не длина списка `[x]`, а **одна честная killer-идея**:
непрерывный градиент проверяемых гарантий на функцию + родная мультиязычность.
Это ниша, которую никто не занял чисто, — и она достижима поверх уже работающего
ядра TIL.

Полные доказательства (30 проб + 7 срезов) с фрагментами сгенерированного C и
выводом программ доступны в материалах аудита; каждая находка в этом документе
привязана к `файл:строка` в `src/til.py`.
